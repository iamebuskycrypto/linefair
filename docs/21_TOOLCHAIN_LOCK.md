## Findings recorded during lock
1. **WASM features:** plain `cargo build` on 1.95.0 emits post-MVP features (bulk-memory, reference-types, multivalue…). cargo-near explicitly checks rustc against the SDK's target protocol (84) and accepted 1.95.0, and the built WASM executed in sandbox. **Only ship `cargo near build` output.** The final WASM carries no `target_features` section (stripped by wasm-opt).
2. **Sandbox vs testnet version skew:** sandbox node is 2.13.4, testnet runs 2.14.0-rc.5 (protocol 88). Behavior that depends on protocol differences (gas costs, limits) must be re-measured on testnet at LF-014.
3. **Lockfile discipline:** after editing dependencies, `cargo near build --locked` fails with a misleading `aws-lc-rs` version-conflict message until `cargo update` (or `cargo generate-lockfile`) refreshes `Cargo.lock`. Always regenerate, review the diff, then build `--locked`.
4. **Reproducible build:** `cargo near build reproducible-wasm` needs Docker (not installed) plus a `[reproducible_build]` section. P0 records the `non-reproducible-wasm` sha256 for each deploy. A reproducible build is a G1 enhancement, and installing Docker needs founder approval.
5. near-sdk refuses host compilation without the `unit-testing` (or `non-contract-usage`) feature (guard at `near-sdk-5.29.1/src/lib.rs:131-142`).
